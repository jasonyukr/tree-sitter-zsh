## OVERVIEW

`tree-sitter-zsh` is a CommonJS Tree-sitter grammar package for zsh source, scripts, and startup files. It is intentionally syntax-only: it produces parse trees for editor/tooling use and does not execute or model shell runtime behavior.

## STRUCTURE

```text
./
  grammar.js             # authoritative grammar source
  src/                   # external scanner plus generated parser artifacts
  queries/               # editor query captures for highlights, locals, aerial
  test/corpus/           # golden Tree-sitter corpus tests
  test/samples/          # parse-only real-world zsh samples
  scripts/               # custom smoke/sample parse runners
  ZSH_SPEC.md            # zsh syntax baseline and parser non-goals
  TODO.md                # completed coverage plan and future fixture notes
```

## WHERE TO LOOK

| Task | Location | Notes |
| --- | --- | --- |
| Change grammar behavior | `grammar.js` | Source of truth; run `npm run generate` afterward. |
| Change heredoc scanning | `src/scanner.c` | Hand-written C scanner; keep token order aligned with `grammar.js` externals. |
| Inspect generated parser state | `src/parser.c` | Generated by Tree-sitter; do not patch by hand. |
| Update node kinds | `src/node-types.json` | Generated from grammar; refresh with `npm run generate`. |
| Update editor captures | `queries/*.scm` | Query names must match generated node types. |
| Add golden parser coverage | `test/corpus/*.txt` | Inline expected trees live beside each fixture. |
| Add real-world smoke coverage | `test/samples/*.zsh` | Parse-only; no expected trees. |
| Check supported zsh scope | `ZSH_SPEC.md` | zsh 5.9.1 release manual is the stable baseline. |
| Run custom gates | `scripts/*.sh` | Require `zsh` and `tree-sitter`. |

## CONVENTIONS

- Keep `grammar.js` CommonJS with `// @ts-check`; there is no TypeScript build step.
- Treat `grammar.js` and `src/scanner.c` as source. Treat `src/parser.c`, `src/grammar.json`, and `src/node-types.json` as generated outputs.
- After grammar changes, run `npm run generate` before tests so generated C and JSON stay in sync.
- The published package surface is constrained by `package.json` `files`: `grammar.js`, `tree-sitter.json`, `README.md`, `LICENSE`, `queries/**`, and `src/**`.
- Recognized file types are `zsh`, `zshrc`, `zprofile`, `zlogin`, `zlogout`, and `zshenv`; keep `package.json` and `tree-sitter.json` aligned.

## ANTI-PATTERNS (THIS PROJECT)

- Do not model runtime option state, alias expansion, glob matching, arithmetic evaluation, module loading, or parameter-expansion execution in the static grammar.
- Do not hand-edit generated parser artifacts to fix behavior; change `grammar.js` or `src/scanner.c`, then regenerate.
- Do not use sample fixtures as golden parse snapshots. Only `test/corpus/*.txt` contains expected trees.
- Do not treat top-level shared libraries such as `parser.so` or `zsh.dylib` as source; they are ignored build artifacts.

## UNIQUE STYLES

- Corpus files use Tree-sitter's heading, input, `---`, expected-tree format.
- Sample tests only require `zsh -n` success and no `ERROR` in `tree-sitter parse -q` output.
- `ZSH_SPEC.md` is the scope authority: accept parser-visible syntax conservatively, but keep runtime-sensitive behavior out of scope.
- Query files are small and direct; prefer explicit captures over broad patterns that assume runtime meaning.
