# src/ KNOWLEDGE BASE

## OVERVIEW

`src/` contains one hand-written external scanner and the checked-in parser artifacts produced by `tree-sitter generate`.

## WHERE TO LOOK

| Task | Location | Notes |
| --- | --- | --- |
| Change heredoc scanner behavior | `scanner.c` | Hand-written C; keep scanner token order aligned with grammar externals. |
| Inspect generated parser tables | `parser.c` | Generated; useful for debugging, not source for fixes. |
| Inspect grammar snapshot | `grammar.json` | Generated from `grammar.js`. |
| Inspect node schema | `node-types.json` | Generated; query captures should match this. |
| Check runtime headers | `tree_sitter/*.h` | Vendored Tree-sitter runtime headers. |

## CONVENTIONS

- `scanner.c` is the only normal edit target in this directory.
- `parser.c`, `grammar.json`, and `node-types.json` should change through `npm run generate`.
- The scanner currently owns heredoc delimiter state with a small queue; preserve serialization and deserialization compatibility when changing scanner state.
- External token names in `scanner.c` must stay in the same order as `externals` in `../grammar.js`.
- Keep scanner failure modes conservative: return `false` when the scanner cannot prove the heredoc token shape.

## ANTI-PATTERNS

- Do not patch `parser.c` to change parse behavior.
- Do not change generated JSON manually to satisfy tests or queries.
- Do not raise heredoc limits casually; `MAX_HEREDOCS` and `MAX_DELIMITER_LENGTH` affect scanner state size.
- Do not add runtime shell semantics here; scanner work should only expose syntax tokens Tree-sitter needs.

## NOTES

- `parser.c` carries the `Automatically @generated by tree-sitter` banner.
- `tree_sitter_zsh_external_scanner_scan` is the external scanner entry point.
- Heredoc body handling strips leading tabs only for `<<-` delimiters.
